◆ Serves()

virtual bool Deki::IMemoryProvider::Serves ( Memory::Region region) const
pure virtual

Check if external RAM (PSRAM, SDRAM, etc.) is available.

Returns
true if external RAM is present and usable

Does this board have region as a distinct place to put memory?

A platform with one heap answers true for the regions it can satisfy and false for the rest — and answering true for "external" when there is no PSRAM is not a lie if every allocation is equally fast, it is a statement that the distinction does not exist here.

Memory asks this once at startup to report what the board has.

Allocate bytes from region.

Parameters
needsDmaThe caller requires a DMA engine to be able to read it. Orthogonal to the region: a framebuffer must be reachable whether it lives in internal RAM or in PSRAM.
Returns
The block, or nullptr — including for a region this board does not serve. There is no substitution.

One entry point rather than one virtual per region, because the set of regions is open: a package can define "rtc" without an engine release, and no interface with a method per region could carry that. A provider dispatches on region.id, which is a compile-time constant, and returns nullptr for anything it does not recognise.

There is no header to read it from, so the heap is asked instead (heap_caps_get_allocated_size on ESP-IDF, _msize on Windows). Used only to keep the byte total honest on free; returning 0 costs accuracy in Memory::LogStats and nothing else.
