Detailed Description

The platform's memory, as the engine sees it, so the engine has no platform-specific allocation code: a microcontroller with external RAM uses its SDK's capability allocator, a part without it or a desktop uses malloc.

◆ Allocate()

virtual void * Deki::IMemoryProvider::Allocate ( Memory::Region region,
size_t bytes,
bool needsDma )
pure virtual

Allocates bytes from region, or returns nullptr, including for a region the board does not serve; it never substitutes another region.

needsDma means a DMA engine must be able to read the block, in any region: a framebuffer must be reachable in internal RAM or PSRAM alike.

One entry point, not a virtual per region, because packages can define new regions (such as "rtc") without an engine release. A provider switches on region.id, a compile-time constant, and returns nullptr for any it does not know.

Implemented in Deki::HostMemoryProvider.

virtual size_t Deki::IMemoryProvider::GetAvailable ( Memory::Region region) const

Bytes still free in region, or 0 when the platform cannot measure it.

It appears in the startup line and in every out-of-memory message, so a provider returning 0 should say in a comment that 0 means "unknown", not "exhausted".

◆ GetRawBlockSize()

virtual size_t Deki::IMemoryProvider::GetRawBlockSize ( void * ptr) const
inlinevirtual

Usable size of a block from AllocateRaw, or 0 when the platform cannot say.

There is no header, so the heap is asked (heap_caps_get_allocated_size on ESP-IDF, _msize on Windows). Only keeps the byte total right on free; 0 costs accuracy in Memory::LogStats and nothing else.

◆ Serves()

virtual bool Deki::IMemoryProvider::Serves ( Memory::Region region) const
pure virtual

True when the board can place memory in region.

A platform with one heap answers true for every region it can satisfy: where all memory is equally fast, "external" without PSRAM is the same place as "internal". Memory asks once at startup to report what the board has.

Implemented in Deki::HostMemoryProvider.
