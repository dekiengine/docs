Detailed Description

Registry that manages available firmware builders.

Holds the backends that packages and plugins contribute, and can load builder DLL plugins from ~/.deki-editor/builders/.

BuildPanel queries this registry to get the right builder for the user's selected platform.

◆ BuiltInProvider

using DekiEditor::BuilderRegistry::BuiltInProvider = void (*)(BuilderRegistry&)

Who supplies the builders that ship with the editor.

The registry used to construct ESPIDFBuilder and NativeBuilder itself, which meant this generic machinery named two concrete backends — and would have made deki-editor.dll depend on the executable once it moved there. The owner of those builders installs a provider instead, and the registry knows nothing about what it will be handed.

◆ EnsureLoaded()

void DekiEditor::BuilderRegistry::EnsureLoaded ( )

Built-ins plus one scan for builder plugins.

Idempotent, and lazy rather than at editor start: FirmwareBuildService is reached by the headless CLI and the MCP server, neither of which goes through the editor's boot path, and those are exactly the routes a CI build takes.

void DekiEditor::BuilderRegistry::Shutdown ( )

Destroy builders and unload plugin modules, in that order.

Must be called explicitly before the process exits, the way PluginLoader::UnloadAllPlugins is: Instance() is a function-local static destroyed after main returns, and unloading a module then runs its detach against already-destroyed editor statics.
