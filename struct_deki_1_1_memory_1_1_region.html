Detailed Description

Where an allocation lives.

The caller says; the engine never guesses.

A region is a name, not an enumerator, so the set of them is open: a package defines one and the engine needs no change to carry it. 

namespace DekiEsp32
{
inline constexpr Deki::Memory::Region Rtc{"esp32.rtc"};
}

A package keeps its regions in its OWN namespace rather than reopening Deki::Memory — which it could not do anyway, a class being closed, and which is the point: two board packages that both want an "Rtc" constant cannot collide, because the language keeps them apart. Where the constant lives is never load-bearing; a region's identity is its hashed name, so moving one between namespaces changes nothing at all.

What a package cannot do is SERVE a region: only the board's IMemoryProvider can, and one that has not heard of "esp32.rtc" returns nullptr and says so by name. Extension is two-sided on purpose — a package names what it needs, a board decides whether it has it.

The name is also the capability name, prefixed: a package that allocates from Region("esp32.rtc") declares platformRequires ["memory:esp32.rtc"], so the build refuses a target without it before anything runs.

The pointer is kept, never copied: a Region is only ever built from a string literal, which has static storage duration.
